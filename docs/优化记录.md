# 性能优化记录

本文件同时记录正式评测结果和已经落地、尚待验证的候选改动。只有带有正式评测数据的章节才能记为成果；未编译、未测试或未正式评测的内容必须明确标注，不能据此宣称性能或正确性已经提升。

## 2026-08-12：MVCC 共享读取与单记录零重复复制

### 改动

- 将 `commit_apply_latch_` 改为读写锁：普通 MVCC 读取使用共享锁，版本发布、GC 和检查点继续使用独占锁。
- 单记录读取把物理记录所有权直接交给 MVCC 可见性判断，去掉一次堆分配和记录复制。
- 未修改 SQL、Wire、快照规则、提交日志和恢复流程。

### 正式评测对比

### 结论

本轮不能记为“优化成功”。排名吞吐小幅提高，p99 下降，但完成率、p50 和连续提交稳定性明显变差，Payment 放弃数也由 5 增至 78。共享读锁可能让读取更容易并发，却增加了独占提交者等待或冲突放弃；这只是待验证假设，报告没有提供锁等待或 I/O profile，不能直接定因。

两次正式评测的装载时间、RSS、磁盘占用和可执行文件大小差异较大，因此它们不是严格受控的单变量 A/B。单记录零复制与共享锁也在同一提交中，无法判断各自贡献。

### 后续判定

1. 分开测量“仅去复制”和“再启用共享读锁”两个版本。
2. 记录 `commit_apply` 读/写等待、`txn_state_latch_` 等待、pending writer 超时和各事务放弃原因。
3. 若共享锁版本仍出现完成率、p50 或零提交桶明显回退，不继续扩大读并发；优先缩短读锁范围或加入防止 writer 饥饿的机制。
4. 所有候选仍须通过功能、隔离、COMMIT 持久化、在线一致性和 SIGKILL 恢复门禁。

## 2026-08-12：提交可见性与堆页并发优化（待验证）

### 状态

- 已完成源码修改和静态差异检查。
- 按要求未编译、未运行单元测试、SQL 测试、并发测试或正式评测。
- 本节只用于记录候选版本，不能记为优化成功，也不能替代决赛正确性门禁。

### 修改目标

针对上一轮共享读取版本出现的独占提交者等待、完成率下降和零提交时间桶增多问题，优先处理提交者饥饿、全局锁持有时间过长以及堆文件单锁串行化，同时保持 Wire、SQL、快照隔离、SSI、WAL 和崩溃恢复语义不变。

### 已完成修改

1. **提交可见性线性化**
   - 将 MVCC 提交流程调整为：完成冲突检查，持久化 COMMIT WAL，应用延迟的堆记录和索引修改，最后分配提交时间戳并发布 pending 版本。
   - COMMIT 成功响应仍在 WAL 持久化之后；新事务不能在物理数据和索引应用完成前观察到该提交版本。
   - WAL 已持久化后的存储或索引异常采用 fail-stop，由恢复流程依据持久化日志重做，避免在进程内把已经持久化的 COMMIT 当成 ABORT 回滚。

2. **写者优先的提交屏障**
   - 新增 `WriterPrioritySharedMutex`。已有读者可以完成；一旦出现等待中的提交、GC 或检查点写者，后到读者不能继续插队。
   - 数据语句在索引定位、堆读取和 MVCC 可见性判断的完整边界内持有共享屏障；隐式提交和异常回滚前显式释放，避免递归加锁和自锁。
   - 版本发布、需要物理应用的提交、插入回滚、GC 和检查点继续使用独占屏障。

3. **缩短事务全局锁和读取锁范围**
   - `prepare_write()` 的物理记录校验移出 `txn_state_latch_`，完成页访问后重新取得事务锁并复核 pending writer 和最新提交版本。
   - 删除提交冲突检查中在事务锁和版本分片锁内访问堆页的保底路径；pending 版本异常缺失时保守判为写冲突。
   - 单记录和批量读取复制完物理记录后立即释放文件锁和页锁，再执行 MVCC 可见性解析。

4. **堆文件页级并发**
   - 将原来的单个 `insert_latch_` 拆分为文件元数据读写锁、整数等值缓存读写锁和固定条带页锁。
   - 不同页面上的读取和 UPDATE 可以并行；同一页面上的更新仍保持互斥。
   - INSERT、DELETE、页扩展、空闲页链表维护和恢复操作仍持有所需的文件级独占锁，避免破坏文件头与 free-list 一致性。
   - `RmScan` 在构造时固定扫描页上界，避免并发扩页时一次扫描不断追逐新页面。

5. **批量读取与 GC 停顿修正**
   - 移除对所有 MVCC 分片版本表的无锁预扫描，按实际 RID 分片加锁，消除并发修改 `unordered_map` 时的数据竞争。
   - 分片内完成可见性解析后按输入位置回填，最终保持 RID 和结果记录原始顺序。
   - 修正首次 MVCC 提交立即触发 GC 的计数问题；现在完成 256 次提交后才触发周期 GC。

6. **回滚幂等性**
   - DELETE 和 UPDATE 回滚在恢复旧索引项或删除新索引项前先检查当前索引内容，避免重复回滚导致重复键或删除不存在的条目。

### 预期收益与风险

- 预期减少提交写者被连续读取请求长期阻塞的概率，改善 Payment 和 NewOrder 完成率以及零提交时间桶。
- 预期降低 `txn_state_latch_` 和表文件全局锁的持有时间，使不同页面上的读取、更新以及多个 WAL 提交请求保留并行机会。
- 提交路径、堆页锁和回滚路径均发生了并发控制修改，静态检查不能证明不存在死锁、竞态、索引不一致或恢复回退。
- 写者优先会在提交高峰暂时阻挡新读者；如果写者持续排队，读延迟可能上升，需要通过分事务延迟和等待计数判断是否过度偏向写者。

1. 先通过编译、单元测试和现有 CTest，再执行功能 SQL、Snapshot Isolation、Serializable、COMMIT 持久化和 SIGKILL 恢复门禁。
