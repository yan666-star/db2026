# 性能优化记录

## 2026-08-12：MVCC 读取并发与单记录复制优化

评测基线为 31.2 NewOrder/min，NewOrder p50 延迟约 19.15 秒；评测机 12 核，但数据库平均 CPU 使用约 3 核，表现出明显的读取串行等待。

- 将 `commit_apply_latch_` 从普通互斥锁改为读写锁。普通单记录读取和批量读取使用共享锁，版本发布、MVCC GC 和检查点相关操作继续使用独占锁。
- 单记录读取完成物理记录复制后，直接把记录所有权转交给 MVCC 可见性判断，去掉原有的第二次堆分配和记录复制。批量读取原有的 move 语义保持不变。

本轮没有修改 SQL、Wire 协议、索引键、快照可见性规则、提交顺序或 WAL 持久化流程。源码已通过 `git diff --check`；由于当前桌面环境无法访问 Linux/VMware 编译环境，尚未完成本轮源码的编译和性能复测。
