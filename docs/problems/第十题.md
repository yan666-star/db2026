# 2026 题目十：基于静态检查点的故障恢复

- **前置题目**：可配置的快照与可串行化隔离级别
- **题目种类**：基础功能
- **推荐知识点**：故障恢复概述、基于 REDO/UNDO 日志的恢复算法、恢复算法 ARIES
- **代码框架**：[RMDB 代码仓库](https://gitlab.eduxiji.net/csc1/csc-db/db2026/-/tree/main/rmdb)

## 1. 题目描述

本题要求实现基于静态检查点的系统故障恢复，包含以下功能：

1. 日志管理器；
2. WAL 机制；
3. 基础故障恢复；
4. 语法功能：通过 `CREATE STATIC_CHECKPOINT;` 命令创建静态检查点；
5. 基于静态检查点的系统故障恢复。

### 1.1 基础故障恢复

基础故障恢复功能需要实现日志管理器。在系统运行过程中，将写操作的日志通过日志缓冲区写入磁盘。

参赛队伍需要实现 WAL（Write-Ahead Log，即先写日志后写数据）机制，以及 REDO/UNDO 日志。在系统发生故障并重启后，系统能够通过 REDO/UNDO 日志进行故障恢复，使数据库恢复到一致性状态。

基础故障恢复在系统重启时，从磁盘中的第一条日志开始扫描。

### 1.2 基于检查点的故障恢复

基于检查点的故障恢复是对基础故障恢复的优化。创建检查点后，系统在故障恢复时从最新的检查点开始扫描日志。

检查点技术会将数据库中的脏数据，即缓冲区中已经被修改但尚未写入磁盘的数据，写入磁盘；同时更新数据库的控制文件和日志文件，以便数据库恢复时能够正确地恢复数据。

检查点有多种实现方式，本题要求实现静态检查点。创建静态检查点时，系统需要停止接收新事务、停止正在运行的事务，并将当前数据库缓冲区中的脏页和日志刷入磁盘。

系统崩溃并重启后，应能够找到最近的检查点，并从该检查点开始将数据库恢复到一致性状态。

## 2. 创建静态检查点

创建静态检查点的具体步骤如下：

1. 停止接收新事务，并停止正在运行的事务；
2. 将仍保留在日志缓冲区中的内容写入日志文件；
3. 在日志文件中写入一条“检查点记录”；
4. 将当前数据库缓冲区中的内容写入数据库；
5. 将日志文件中检查点记录的地址写入“重新启动文件”。

## 3. 使用静态检查点进行故障恢复

使用静态检查点进行故障恢复的步骤如下：

1. 在重新启动文件中找到最后一个检查点在日志文件中的地址。将创建检查点时刻的所有事务加入 Undo List，Redo List 暂时为空；
2. 从检查点开始扫描日志。如果有新开始的事务，则将其加入 Undo List；如果有事务提交，则将其从 Undo List 中删除，并加入 Redo List；
3. 对 Undo List 中的所有事务执行 UNDO 操作，对 Redo List 中的所有事务执行 REDO 操作。

关于静态检查点的详细内容，可以参考教材《数据库管理系统原理与实现》第 12 章“故障恢复”。

## 4. 测试示例

### 4.1 不带检查点的系统故障恢复

```sql
CREATE TABLE t1 (id INT, num INT);

BEGIN;
INSERT INTO t1 VALUES (1, 1);
COMMIT;

BEGIN;
INSERT INTO t1 VALUES (2, 2);

-- 系统接收到终止信号
CRASH;
```

重启系统后执行：

```sql
SELECT * FROM t1;
```

### 4.2 带检查点的系统故障恢复

```sql
CREATE TABLE t1 (id INT, num INT);

BEGIN;
INSERT INTO t1 VALUES (1, 1);
COMMIT;

-- 创建静态检查点
CREATE STATIC_CHECKPOINT;

BEGIN;
INSERT INTO t1 VALUES (2, 2);

-- 系统接收到终止信号
CRASH;
```

重启系统后执行：

```sql
SELECT * FROM t1;
```

## 5. 测试点说明

| 测试点 | 详细说明 |
| --- | --- |
| `crash_recovery_single_thread_test` | 单线程发送事务，数据量较小，不包括建立检查点。 |
| `crash_recovery_multi_thread_test` | 多线程发送事务，数据量较小，不包括建立检查点。 |
| `crash_recovery_index_test` | 单线程发送事务，包含建立索引，数据量较大，不包括建立检查点。 |
| `crash_recovery_large_data_test` | 多线程发送事务，数据量较大，不包括建立检查点。 |
| `crash_recovery_without_checkpoint` | 单线程发送事务，数据量巨大，不包括建立检查点。记录系统故障恢复时间 `t1`。恢复时间指从 Server 重启开始，到 Server 能够提供服务为止所需的时间。 |
| `crash_recovery_with_checkpoint` | 单线程发送事务，数据量与 `crash_recovery_without_checkpoint` 相同。执行过程中会不定时发送 `CREATE STATIC_CHECKPOINT;` 建立检查点。系统 Crash 后记录恢复时间 `t2`。当 `t2` 不超过 `t1` 的 70%，并且通过一致性检测时，视为通过本测试点。 |

### 6.5 统计恢复时间

由另外一个线程持续尝试重新连接，仅最后两个测试点需要统计恢复时间。

```cpp
std::string query = "select * from district;";
time_t start_time = now();

while (true) {
    ret = connect_database("rmdb");
    if (ret == 0) {
        if (run_query(query)) {
            // 重连成功且事务执行成功，视为系统恢复完成。
            break;
        }
    }
    sleep(0.05);
}

time_t end_time = now();
time_t recovery_time = end_time - start_time;
```
