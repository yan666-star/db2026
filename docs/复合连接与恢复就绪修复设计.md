# 复合连接与恢复就绪修复设计

## 目标

在不改变决赛 Wire v3、SQL 语义、TPC-C 工作负载、MVCC 可见性、WAL 持久化和 COMMIT 应答顺序的前提下，消除 Post-crash Recovery 的三类失败：重启后关系批处理超时、active loser 恢复唯一键冲突、正式规模恢复 readiness 超时或监听瞬时失败。

## 范围与顺序

本次只修改 `src/` 内的通用数据库机制，按以下三个独立提交实施：

1. 复合 JOIN 全绑定和最长连续索引前缀选择。
2. active loser 的 REDO 跳过及恢复索引键变更判断。
3. 增量 free-list 恢复、最小恢复刷写、checkpoint 快照复制和监听重试。

不复制 `D:\DMS-DESIGN\dbg\db2026\src` 的完整目录；该参照版本与当前 Wire/服务端结构不同，只逐项移植已验证的语义和必要接口。

## 1. 复合 JOIN 全绑定

### 问题

当前嵌套循环连接在每个外表行只把第一个跨表等值条件传给内表索引。复合索引的其余列没有常量条件时，内表拒绝 lookup 并退化为全扫。`new_orders(no_w_id,no_d_id,no_o_id)` 与 `orders(o_w_id,o_d_id,o_id)` 的关系检查因此接近二次方。

### 设计

- 新增 `IndexLookupBinding`，包含目标列、外表字段地址、类型与长度。
- `AbstractExecutor::set_index_lookup()` 接受完整 binding 集合。
- `NestedLoopJoinExecutor` 收集当前外表行能提供的全部跨表 `EQ` 绑定后一次传给右侧执行器。
- `FilterExecutor` 与 `ProjectionExecutor` 原样透传 binding 集合。
- `IndexScanExecutor` 沿索引列顺序优先使用动态绑定，再使用本表常量等值条件；只有形成至少一个真实连续前缀时才启用 lookup。完整键用 `get_value`，真前缀用已有类型正确的上下界范围扫描。
- `Planner` 根据“连接等值列与内表常量等值条件”覆盖的最长连续索引前缀选择内表索引；同分选择列数更少的索引，并记录完整索引身份。
- 索引访问仅是候选行缩减；最终仍执行原有所有 JOIN/WHERE 条件。

### 正确性约束

- 未绑定列不得被当作零值等值条件。
- 绑定类型和长度必须与索引列一致；不匹配则放弃索引访问并保留通用连接结果。
- 不按表名、SQL 文本、仓数、订单号或评测阶段分支。

## 2. Active loser 恢复

### 问题

分析阶段已经识别最终 active 的 loser，但当前 REDO 只记录其动作 offset，仍继续重放 INSERT/DELETE/UPDATE。若 loser 与 committed winner 暂时具有相同唯一索引键，恢复会在 UNDO 前抛唯一键冲突并退出。

### 设计

- REDO 遇到最终 active loser 的动作时，把 offset 放入 `loser_action_offsets_` 后立即跳过物理操作。
- UNDO 保持逆序执行幂等 INSERT/DELETE/UPDATE 反操作，并在 undo 落盘后写 ABORT WAL。
- committed 和既有 aborted 事务的行为保持不变。
- 恢复 UPDATE 仅当 WAL old/new 的某一索引键不同才修改该索引；非键列更新不得执行 delete/insert 索引 churn。

## 3. 正式规模恢复与监听

### 问题

当前 `finish_recovery()` 对每个 touched 表全量 `rebuild_free_page_list()`，并 `flush_for_checkpoint()` 全库；正式 50 warehouse 数据中会重复扫描千万行表和同步全部索引。快照索引复制仍是 iostream 全量复制。监听端口只 bind 一次，SIGKILL 后短暂占用会直接退出。

### 设计

- 恢复 INSERT/DELETE/UPSERT 按页面最终满/非满状态增量维护 free-list，保证 checkpoint 文件头滞后时仍可恢复。
- 删除对所有 touched 表的全表 free-list rebuild；仅保留没有 checkpoint 索引快照时确有必要的表级修复。
- `finish_recovery()` 只刷写 touched heap 表，避免把全部 live 索引同步纳入 readiness 临界路径。
- checkpoint 文件复制使用 `std::filesystem::copy_file(...overwrite_existing)` 并保留错误信息。
- listener 对 `EADDRINUSE` 等短暂资源错误创建新 socket 后有限重试；其他错误立即失败。

## 验证门槛

每项先添加能在旧实现失败的测试，再实现生产代码：

1. 三列等值 JOIN 对复合索引形成完整 lookup，结果仍满足全部条件。
2. active loser 更新唯一键、winner 提交同一键、SIGKILL 后重启可 SQL 测活且 loser 不可见。
3. 恢复 INSERT/DELETE 与旧 checkpoint 文件头组合下 free-list 一致；监听端口短暂占用后可重新监听。
