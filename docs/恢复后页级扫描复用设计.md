# 恢复后页级扫描复用设计

## 1. 背景与目标

平台已经通过功能、恢复、持久性和数据加载检查，但在 SIGKILL 后重启的完整一致性检查中，`EXEC_BATCH` 在响应截止时间内没有执行完成。服务进程和监听端口仍然存在，说明当前主要问题不是进程退出或响应帧短写，而是批次中的大表聚合扫描耗时过长。

现有顺序扫描按页读取记录，但 `RmFileHandle::batch_get_records()` 会为每条有效记录分别构造一个拥有独立数据缓冲区的 `RmRecord`。在数千万行数据的恢复后一致性聚合中，这会产生大量重复的堆分配与释放。

本次改造的目标是：复用顺序扫描中的记录对象和数据缓冲区，减少逐行堆分配，同时保持决赛文档要求的 SQL、事务、恢复和 Wire v3 行为不变。

## 2. 方案选择

采用执行器局部记录缓冲池方案。

- 缓冲池由单个 `SeqScanExecutor` 实例独占，不跨查询、线程或连接共享。
- 第一批记录按需分配；记录不再被当前执行位置引用后，归还扫描器的空闲池。
- 后续页面优先复用大小匹配的 `RmRecord` 及其内部数据缓冲区。
- 仍然把页面中的记录内容复制到执行器拥有的记录中，不引入跨页面的非拥有指针。

不采用以下高风险方案：

- 不让执行器长期持有缓冲池页面指针，避免改变页面固定和淘汰行为。
- 不绕过 BufferPoolManager 使用 mmap 或直接文件扫描，避免读取未落盘脏页或破坏恢复一致性。
- 不针对某个 TPC-C 表或某条隐藏检查编写特例。
- 不融合或改写聚合、条件判断与 MVCC 可见性语义。

## 3. 数据流与生命周期

改造后的单页扫描流程如下：

1. `SeqScanExecutor` 收集当前数据页上的有效 RID。
2. 将空闲记录缓冲区传给批量读取接口。
3. 批量读取优先取得大小匹配的空闲记录；没有可用记录时才新建记录。
4. 在现有锁保护下把页面记录复制到对应缓冲区。
5. 按现有流程执行 MVCC 可见性过滤；需要历史版本时仍由 MVCC 路径返回独立记录。
6. 按现有流程执行谓词判断并保持记录与 RID 对齐。
7. 上层调用 `Next()` 后，上一条不再被引用的物理记录归还空闲池。
8. 被过滤、不可见或未返回给上层的记录立即归还空闲池。

记录池只保存拥有自身内存的 `RmRecord`。池内记录必须满足记录长度与当前表的记录长度一致；不一致时不得复用。

## 4. 正确性边界

本次修改不改变以下行为：

- Wire v3 请求、响应和 `EXEC_BATCH` 的单一 `BATCH_RESULT` 终止语义。
- SQL 解析、绑定、谓词计算、聚合结果和 TPC-C 工作负载。
- MVCC 快照、版本选择、SSI 冲突检测和事务时间戳。
- WAL 写入、COMMIT 刷盘、提交可见性和提交响应顺序。
- REDO、UNDO、检查点和崩溃恢复流程。
- BufferPoolManager 的取页、脏页和淘汰协议。
- `commit_apply_latch_`、文件页锁和 MVCC 锁的既有获取顺序。

上层能够观察的当前记录在下一次 `Next()` 前保持有效。执行器不会在记录仍可能被上层使用时回收或覆盖其缓冲区。

## 5. 接口范围

计划只修改以下最小范围：

- 为 `RmFileHandle::batch_get_records()` 增加可选的记录复用输入，或增加语义等价的重载。
- 在 `SeqScanExecutor` 中维护当前批次记录、当前返回记录和空闲记录池。
- 增加最小的记录层或执行器单元测试，验证复用及结果正确性。

`AggregationExecutor` 不增加特殊扫描接口，也不改变聚合算法；它只通过已有的 `current_record()` / `Next()` 契约获得下层改造收益。

## 6. 异常与降级处理

- 空闲池为空时正常分配新记录，不影响查询正确性。
- 记录长度不匹配时丢弃该复用候选并正常分配。
- MVCC 返回替代版本时，不把仍被结果集合引用的对象提前放回空闲池。
- 查询异常退出时，记录对象由 RAII 自动释放，不建立全局残留状态。
- 若复用无法覆盖某条路径，允许该路径保留原分配行为，不以牺牲正确性换取完整复用率。

## 7. 验证方案

先增加能够失败的聚焦测试，再修改实现：

1. 连续读取两个批次，验证记录对象或内部数据缓冲区得到复用。
2. 验证复用后的字段内容来自新批次，不残留旧记录内容。
3. 验证条件过滤后记录与 RID 仍严格对应。
4. 验证不可见记录和 MVCC 替代版本不会被错误复用。
5. 运行现有顺序扫描、聚合、批量可见性和恢复相关测试。
6. 执行 `git diff --check` 并检查中文文档编码和代码差异。

本地没有平台使用的完整 2500 万行数据库，因此单元测试和小规模回归只能证明接口与语义正确，不能单独证明平台的 126 秒超时已经消失。最终性能结论仍以完整数据或平台复测为准。

## 8. 验收标准

- 功能、恢复、持久性和 LOAD 语义不退化。
- 顺序扫描在预热一页后不再为每条物理记录反复分配同尺寸数据缓冲区。
- 执行器对外记录生命周期保持不变。
- 不增加全局共享状态，不改变锁顺序。
- 不引入 TPC-C 或平台检查专用分支。
