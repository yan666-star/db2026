# 线下决赛资格赛：改动总览与索引

> 本文是全部“详细讲解”文档的入口。先读本文件了解**改动链全貌**，再按需跳进单个文件讲解。讲解原稿多来自功能扩展线；当前答辩主线为 `xin`，ExtendedJoin 等扩展可能默认关闭，以仓库代码为准。

## 一、一句话认识数据流

```text
SQL 字符串
  → lex.l          （字符 → token）
  → yacc.y         （token → AST 树）
  → ast.h          （AST 节点定义，含 SemValue）
  → Analyze        （AST → Query：列绑定、类型检查、条件转换）
  → Planner        （Query → Plan 树：索引选型、左深 Join、投影/聚合）
  → plan.h         （Plan 节点定义）
  → Portal         （Plan 树 → Executor 树，分流 INNER / 扩展 JOIN）
  → Executor       （火山模型：beginTuple/Next/nextTuple 逐行产结果）
  → QlManager      （消费结果并打印）
```

**加一个功能的本质**：在每一层留下"这个功能的标记/参数"，让上层能感知。任何一层漏传，功能就会静默消失或走默认路径。

## 三、四条"最小实现"路线图（对齐 docs 资格赛模拟题）

### 路线 A：新增 JOIN 类型（SEMI/ANTI，最可能考）

文件改动链（按现场手写顺序）：

```text
1. ast.h:      JoinType 加 SEMI_JOIN；FromClause/SelectStmt 的 join_types 改 #if 1
2. lex.l:      "SEMI" { return SEMI; }（行首规则，放标识符前）
3. yacc.y:     %token SEMI；tableList 加 SEMI JOIN 产生式（注意 $4/$6）；select_branch 传 join_types
4. analyze.h:  Query::join_types 改 #if 1
5. analyze.cpp: analyze_select 里 query->join_types = x->join_types; + ANTI 右表列校验
6. plan.h:     启用带 JoinType 的 JoinPlan 构造
7. planner.cpp: make_one_rel 左深循环按 query->join_types[i-1] 传 type
8. executor_extended_join.h: #if 1；SEMI 分支（有匹配输出一次左行）
9. portal.h:    #if 1；非 INNER 走 ExtendedJoinExecutor
```

关键约定（三处必须一致）：

```text
join_types[i] = 把 tables[i+1] 接到左深树时使用的类型
join_types.size() == tables.size() - 1
```

必测边界：一对一、一对多（只输出一次）、左行无匹配、右表空、左表空、`SELECT *`、右表列、普通 JOIN 回归。

### 路线 B：CROSS JOIN（最省事）

只改 `lex.l`（`"CROSS" { return CROSS; }`）+ `yacc.y`（`%token CROSS` + 无 ON 的 `CROSS JOIN tableRef` 分支）。执行层**不用改**——`NestedLoopJoinExecutor` 空条件 = 所有组合匹配，Planner 空 `join_conds` 合法。M×N 行、任一侧空结果空。

### 路线 C：BETWEEN（只改 parser）

`lex.l` 加 token → `yacc.y` 加 `betweenCondition` 产生式，展开成 `GE` + `LE` 两个 `BinaryExpr` → 接进 `whereClause` 两个位置（首项 + AND 组合）。后续层完全复用。边界包含、不交换上下界、`NOT BETWEEN` 拒绝。

### 路线 D：SELECT DISTINCT（改 parser → Plan → ProjectionExecutor）

```text
1. lex.l:   "DISTINCT" { return DISTINCT; }
2. yacc.y:  %token DISTINCT；opt_distinct 非终结符；select_branch 改（注意 $n 右移）
3. ast.h:   SelectStmt::is_distinct = false
4. analyze.h: Query::is_distinct = false
5. analyze.cpp: query->is_distinct = x->is_distinct; + 组合限制
6. plan.h:  ProjectionPlan 参数尾部加 is_distinct
7. planner.cpp: generate_select_plan 传 query->is_distinct
8. executor_projection.h: 状态机重构（project_current + seek_unique），先去重再 LIMIT 再计数
```

必测：单列重复、多列整行去重、`DISTINCT *`、空表、全重复、`DISTINCT ... LIMIT 2`（先取前两行再去重是错的）。

## 四、通用变量百科（跨文件都出现）

| 变量名 | 类型 | 出现位置 | 含义 |
|---|---|---|---|
| `cols_` | vector\<ColMeta> | 所有 Executor/ScanPlan/ProjectionPlan | 输出记录的 schema；**offset 必须对应当前输出记录** |
| `len_` / `tupleLen()` | size_t | 所有 Executor | 输出记录字节数 |
| `current_rec_` | unique_ptr\<RmRecord> | Join/Scan/Project | "当前已定位、等待 Next() 取走"的记录 |
| `is_end_` | bool | 所有 Executor | 是否没更多结果；找到结果置 false，耗尽 reset+true |
| `fed_conds_` | vector\<Condition> | Scan/Filter/Join | 实际用于 eval_conditions 的谓词（从 conds 复制/接管） |
| `plan_` | 具体 Plan\* | 所有 Executor | 借用指针；`plan_->rows_++` 统计 |
| `sel_idxs_` | vector\<size_t> | Projection | 投影列在下层 schema 的下标 |
| `limit_` / `result_idx_` | int | Projection | 输出上限 / 已输出数 |
| `left_` / `right_` | unique_ptr | Join | 左右子执行器 |
| `join_types` | vector\<JoinType> | FromClause/SelectStmt/Query | 每条 Join 边的类型（#if 0） |
| `raw` | shared_ptr\<RmRecord> | Value | 字面量物理字节，init_raw 后有效 |

## 六、现场手写自检清单

```text
□ 新关键字：lex 返回 + yacc %token 两边闭环
□ 产生式加 token 后重新数 $1..$n（标点和关键字都占位置）
□ AST 字段 → Query → Plan → Executor 全程传递（每层都要查）
□ Query/Plan 新字段带默认值（保持旧行为）
□ 列限制在列绑定完成后判断
□ 常量 init_raw 用列 len
□ DISTINCT 先于 LIMIT 先于 rows_ 计数
□ JOIN 右侧对每个左行重置 beginTuple
□ 空表边界：左空/右空/都空
□ 不支持的组合显式抛 failure（不要静默忽略）
□ EXPLAIN ANALYZE 的 rows_ 与实际输出一致
□ 普通 SELECT/JOIN/LIMIT 回归不受影响
```

## 七、讲稿速记（最后复习用）

**四接口**：`beginTuple`=定位首条；`Next`=取当前（不推进）；`nextTuple`=找下一条；`is_end`=没结果了。

**JOIN 状态**：`right_buffer_`=右表物化；`right_idx_`=当前查第几条；`left_has_match_`=当前左行是否匹配过；`right_matched_`=每条右行是否匹配过；`scanning_unmatched_right_`=RIGHT/FULL 第二阶段。

**SEMI vs ANTI**：SEMI 有匹配就输出左行一次（先推进左游标再返回）；ANTI 扫完右表仍无匹配才输出左行。两者输出 schema 只含左列，但**条件求值仍需要左+右两套 cols**。

**为什么要有两套 cols**：`cols_`（对外输出，SEMI/ANTI 只有左）vs `eval_cols_`（条件求值，永远是左+右）。

**DISTINCT 顺序**：先去重 → 再 LIMIT → 再 rows_++。key 用 `std::string(data, size)` 带长度。
