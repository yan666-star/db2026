# 计划与执行模块说明

面向 RMDB 的 **optimizer（计划）** 与 **execution（执行）** 两层：原理、文件组成、Plan↔Executor 对应关系，以及推荐阅读顺序。

## 1. 在整条 SQL 流水线中的位置

```text
SQL 文本
  → Parser（AST）
  → Analyze（Query）
  → Optimizer / Planner（Plan 树）     ← 计划模块
  → Portal（Plan → Executor 树）       ← 桥梁（必懂）
  → Executors（拉元组）               ← 执行模块
  → QlManager（打印 / DDL / DML）
```

| 层 | 回答的问题 | 是否碰页面 |
|----|------------|------------|
| Analyze | SQL 语义是否合法、列/表是什么 | 否（读元数据） |
| **Planner** | **用什么算子、怎么拼成树** | 否 |
| **Executor** | **真正扫表、连接、投影、改数据** | 是 |

```text
Query（语义结果）
   ↓  Optimizer / Planner
Plan 树（怎么做，还不动数据）
   ↓  Portal::convert_plan_executor
Executor 树（真正扫表 / 连接 / 投影）
   ↓  beginTuple / Next / nextTuple
RmRecord 流 → output.txt / 客户端
```

## 2. 计划模块（`src/optimizer/`）

### 2.1 原理

计划层只构造带 `PlanTag` 的计划节点，**不读写页面**。真正 I/O 在执行层。

入口顺序：

1. **`Optimizer::plan_query`**：按语句类型分流  
   - `HELP` / `SHOW` / 事务 / `SET` → `OtherPlan` / `SetKnobPlan` 等（几乎无子树）  
   - DDL / DML / `SELECT` → **`Planner::do_planner`**
2. **`Planner::do_planner`**：按 AST 建根计划（建删表索引、Insert/Delete/Update、Select）
3. **`SELECT` 路径：`generate_select_plan`**  
   - `logical_optimization`（当前较薄）  
   - `physical_optimization` → **`make_one_rel`**（表扫描 + 左深 Join + 谓词下推）  
   - 再套 `Sort` / `Aggregate`，或普通 `Projection`

典型 `SELECT` 计划形状（自底向上）：

```text
DMLPlan(T_select)                          ← Portal 认这个根
  └─ ProjectionPlan / AggregatePlan
       └─ SortPlan?（有 ORDER BY 且非聚合内排序时）
            └─ JoinPlan（多表左深树）
                 ├─ Filter? / Project? / ScanPlan | UnionPlan | 派生表
                 └─ ...
```

要点：

- 单表条件尽量压到扫描侧（`pop_conds` / `FilterPlan`）
- 索引用**最左前缀**（`get_index_cols`）选 `T_IndexScan`，否则 `T_SeqScan`
- 派生表 / UNION：在 `make_one_rel` 里对 `derived_tables` 递归 `generate_subquery_plan`，集合算子挂 `UnionPlan`

### 2.2 文件组成

| 文件 | 职责 |
|------|------|
| `optimizer.h` | **Optimizer**：查询类型总分流，薄封装 |
| `planner.h` / `planner.cpp` | **Planner**：建树；索引选择、Join 左深树、派生表/UNION、投影/聚合/排序 |
| `plan.h` | **全部 Plan 节点** + `PlanTag`；节点上的 `rows_` 供 `EXPLAIN ANALYZE` |

### 2.3 主要 Plan 节点（`plan.h`）

| 类 | 含义 |
|----|------|
| `ScanPlan` | 顺序扫 / 索引扫（`T_SeqScan` / `T_IndexScan`） |
| `FilterPlan` | 显式过滤（谓词下推后的层） |
| `JoinPlan` | 嵌套循环连接（现默认 `INNER_JOIN`） |
| `ProjectionPlan` | 投影 + 可选 `LIMIT` |
| `SortPlan` | 多列排序 |
| `AggregatePlan` | GROUP BY / 聚合 / HAVING |
| `UnionPlan` | 集合算子（UNION / INTERSECT / EXCEPT 等） |
| `DMLPlan` | SELECT / INSERT / UPDATE / DELETE 外壳（SELECT 的查询树在 `subplan_`） |
| `DDLPlan` | 建删表 / 索引 |
| `OtherPlan` 等 | 工具命令 / 事务 / 开关 |

读计划时优先看**字段**（`left_` / `right_` / `subplan_` / `conds_` / `sel_cols_`），再看 `tag`——`tag` 决定 Portal 映射到哪个执行器。

### 2.4 Planner 关键入口函数

| 函数 | 作用 |
|------|------|
| `do_planner` | DDL/DML/SELECT 总入口 |
| `generate_select_plan` | SELECT：逻辑优化 → 物理优化 → 投影或聚合 |
| `physical_optimization` / `make_one_rel` | 为 FROM 中每张表建 Scan，拼 Join，挂 Filter |
| `generate_subquery_plan` | 派生表 / UNION 分支子计划 |
| `generate_sort_plan` | ORDER BY → SortPlan |
| `get_index_cols` | 最左前缀选索引列 |

## 3. 桥梁：Portal（`src/portal.h`）

Portal **不属于** `optimizer/`，但计划和执行之间必须经过它。

| 方法 | 作用 |
|------|------|
| `Portal::start` | 按根 Plan 打 `portalTag`（普通 SELECT、EXPLAIN、DML、DDL、工具） |
| `convert_plan_executor` | **递归**把 Plan 树镜像成 Executor 树 |
| `Portal::run` | 交给 `QlManager` 拉结果或执行 DDL/DML |

没有 Portal，计划树不会变成可执行算子。

## 4. 执行模块（`src/execution/`）

### 4.1 原理：Volcano（火山模型）

每个算子实现同一套接口（`executor_abstract.h`）：

| 接口 | 作用 |
|------|------|
| `beginTuple()` | 打开子树、定位第一条 |
| `Next()` | 返回当前行（`RmRecord`） |
| `nextTuple()` | 推进到下一行 |
| `is_end()` | 是否结束 |
| `cols()` / `tupleLen()` | 输出 schema |

上层要一行，就向子节点要一行（Join / Sort / Union 等常先物化再吐出）。  
扫描层通过 `RmFileHandle` / `IxHandle` 读页；`Context` 携带事务、锁、日志等。

`QlManager::select_from` 核心循环：

```text
root->beginTuple();
while (!root->is_end()) {
    rec = root->Next();
    打印一行;
    root->nextTuple();
}
```

### 4.2 文件组成

| 文件 | 职责 |
|------|------|
| `executor_abstract.h` | 算子基类 + 列名查找 |
| `executor_seq_scan.h` | 全表扫；谓词；MVCC 可见性；可给 Filter 计 `rows_` |
| `executor_index_scan.h` | 索引范围 / 点查 |
| `executor_filter.h` | 独立过滤（部分路径） |
| `executor_nestedloop_join.h` | 内连接 NLJ |
| `executor_extended_join.h` | LEFT / ANTI 等扩展（常 `#if 0`） |
| `executor_projection.h` | 投影 / LIMIT |
| `execution_sort.h` | 排序 |
| `executor_aggregation.h` | 聚合 |
| `executor_union.h` | 集合算子 |
| `executor_insert.h` / `update.h` / `delete.h` | 改表并维护索引 |
| `execution_eval.h` | 条件求值公共逻辑 |
| `execution_manager.h` / `.cpp` | **QlManager**：拉 SELECT、跑 DDL/工具、打印、`EXPLAIN ANALYZE` |
| `execution_defs.h` / `execution.h` | 头文件聚合 |

### 4.3 Plan ↔ Executor 对应

| Plan | Executor |
|------|----------|
| `ScanPlan(T_SeqScan)` | `SeqScanExecutor` |
| `ScanPlan(T_IndexScan)` | `IndexScanExecutor`（MVCC 下可能强制 SeqScan） |
| `FilterPlan` | `FilterExecutor`（或与 Scan 协作计行） |
| `JoinPlan` | `NestedLoopJoinExecutor`（扩展类型 → Extended） |
| `ProjectionPlan` | `ProjectionExecutor` |
| `SortPlan` | `SortExecutor` |
| `AggregatePlan` | `AggregationExecutor` |
| `UnionPlan` | `UnionExecutor` |
| `DMLPlan(Insert/Update/Delete)` | 对应 Insert / Update / Delete Executor |
| `DDLPlan` | 不经算子树，`QlManager::run_mutli_query` 调 `SmManager` |

## 5. 总览图

```text
                 ┌─ optimizer.h          分流 HELP / 事务 / …
    Query ──► Optimizer
                 └─ planner.cpp          建 Plan 树
                           │
                        plan.h 节点
                           │
                      portal.h 镜像转换
                           │
           ┌───────────────┴───────────────┐
      叶：Scan / Index                中：Join / Filter
      上：Proj / Sort / Agg / Union
                           │
                 AbstractExecutor::Next()
                           │
                   execution_manager
                      打印 / DDL
```

## 6. 加新算子时的固定触点

```text
plan.h 增加 Plan 节点
  → planner.cpp 挂到树上
  → portal.h 的 convert_plan_executor 做映射
  → execution/executor_xxx.h 实现 Volcano 接口
  → （如需）execution_manager 打印 / EXPLAIN
```

集合算子（UNION / INTERSECT / EXCEPT）即按此链扩展：`UnionPlan` + `UnionExecutor`。

---

## 7. 推荐阅读顺序

**计划**

1. `plan.h` — 节点字段与 `PlanTag`
2. `optimizer.h` — 分流
3. `planner.cpp`：`do_planner` → `make_one_rel` → `generate_select_plan`

**执行**

1. `executor_abstract.h` — 接口
2. `portal.h`：`convert_plan_executor`
3. `executor_seq_scan.h` → `executor_nestedloop_join.h` → `executor_projection.h`
4. `execution_manager.cpp`：`select_from` / `explain_analyze`
