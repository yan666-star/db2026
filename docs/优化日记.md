## 保留的有效优化

### 1. 纯内存 MVCC abort 免强制刷盘（+29.7% tpmC）

**思路：** 区分三类 abort——纯 MVCC 内存 abort（仅 pending 版本，未触及物理表）、物理回滚 abort（INSERT 等）、已进入 commit 应用阶段的 abort。第一类 ABORT 日志仍写入有序缓冲区，但不单独 fsync；若崩溃丢失，恢复会将事务当 loser 重做 undo，物理表本就是旧正确状态。

**效果：** ABORT 强制刷盘从 ~7500 次降至 ~686 次，8007 次安全跳过；强制刷盘耗时从 4.29s 降至 0.52s。物理回滚仍走完整 checkpoint flush 路径。16-client tpmC 从 605→785（+29.7%），TPS 从 140→173。

### 2. Pending writer 有限等待（预算 2000us）

**思路：** 遇到 pending writer 时不立即 abort，短时间等待 writer 结束。若 writer abort 则可继续提交；若 writer commit 则必然因 `latest_commit > start_ts` 而 abort。诊断按 writer committed/aborted/timeout 分类统计。

**效果：** 2000us 预算下 ~68% 已解决等待来自 writer abort，确实挽救了部分事务。0us（不等待）总 TPS 高但 NewOrder tpmC 低。默认保留 2000us。

### 3. BufferPool 页表共享锁 + per-frame 状态锁（+4.5% tpmC）

**思路：** 诊断显示 BufferPool 全局 latch 是第一锁热点（22s 累计等待）。命中/unpin 路径改为页表共享锁；每个 frame 独立保护 `pin_count/is_dirty`；淘汰/装页/删除/全量 flush 仍用独占锁。

**效果：** 页表平均等待从 10.10us→8.00us（-20.8%），frame 平均等待仅 0.052us。tpmC 829→867（+4.5%），TPS 167→177（+5.7%）。

### 4. 索引点查去临时堆分配（+4.57% tpmC）

**思路：** `IxIndexHandle::get_value` 原先在每层 B+ 树页面上创建/销毁堆分配 `IxNodeHandle`。改为栈上轻量句柄逐层读取，fetch/unpin 顺序、键比较、锁范围不变。对任意 B+ 树唯一键点查生效。

**效果：** 三轮中位数从 852→891（+4.57%），新版本最低一轮仍高于旧版本最高一轮。

### 5. Parser 全局锁范围缩短

**思路：** 生成的 lexer/parser 使用全局 `ast::parse_tree` 需串行执行。改为在锁内复制根 `shared_ptr` 并释放 lexer buffer，随后语义分析/优化/执行在锁外进行。不改变 AST 内容，仅移除无关客户端间的解析串行等待。

**效果：** 已合并到主线。正式测量诊断显示 parser 全局锁累计等待 20.78s，仍为最大单一热点。

## 2026-07-12 Task 7：commit-apply 独占锁范围缩短（+20.4% tpmC）

**思路：** 诊断中 commit-apply read 累计等待 7.66s，根因是 `commit_mvcc()` 在独占锁下既做版本发布（纯内存、微秒级）又做物理应用（含磁盘 I/O、毫秒级）。一个 NewOrder 的全部索引维护都在此锁内，期间所有 reader 被阻塞。

将 commit_mvcc 拆为两阶段：
1. **Phase 1（版本发布）**：独占 `commit_apply_latch_` + `mvcc_latch_` 下执行冲突检查 → 分配 commit_ts → 标记 pending 版本为已提交 → 释放独占锁。`check_commit_conflict_under_latch()` 内已调用 `validate_pending_physical_before()` 做物理 before-image 预验证。
2. **Phase 2（物理应用）**：在全局锁外执行 `delete_indexes → delete_record → update_record → update_indexes`。不重复 `check_physical_before()`，因为 Phase 1 已验证且 SI 冲突检测阻止其他 writer 修改这些记录。

**正确性保证：**
- 读者通过版本链读取——commit_ts 发布后，`get_visible_record_under_latch()` 从版本链 `data` 返回新值，不依赖物理记录
- COMMIT 日志仍在物理应用完成后写入，崩溃恢复语义不变
- 物理应用使用 per-file `insert_latch_` 和 per-index `root_latch_` 做表/索引级串行

**效果（16 clients quick，同环境 A/B）：**

| 指标 | 基线 | Phase A | 变化 |
| --- | ---: | ---: | ---: |
| NewOrder tpmC | 133.95 | **161.26** | **+20.4%** |
| 测量阶段 aborts | 1934 | 1497 | -22.6% |
| 并发一致性 | PASS | PASS | ✅ |
| 压测后一致性 | PASS | PASS | ✅ |
| kill-9 恢复 | PASS | PASS | ✅ |

所有正确性闸门通过。tpmC 提升、abort 减少——reader 不再被 writer 物理应用阻塞，事务执行更快、冲突窗口更短。
